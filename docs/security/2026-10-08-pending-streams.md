# 反向转发待处理流与断开连接安全审查（2026-10-08）

## 确认的问题

`receiveControlSocket` 原先提交工作线程，读取完整控制包及认证 EOF；`receiveSocket` 原先直接提交工作线程，读取完整隧道魔数、版本与路由 UUID。这些读取没有独立的总时限或本插件自己的容量限制，尚未读出路由的 socket 也没有加入任何授权连接组。

核心 API 的通道池提供另一层并发限制，60 秒空闲超时和会话 TTL 也提供时间边界。但有效的非空数据会刷新空闲时间，已导入公钥且未被设为不信任的远端可慢速补齐元数据，占用流槽位与工作任务很久。默认会话 TTL 为 60 分钟，不能将这里描述为完全没有任何资源边界。

本插件 `disconnect()` 原先只关闭监听器及已加入授权组的连接，未关闭尚在读取的控制/隧道 socket。更进一步，控制读取完成后排队的 `clientCall` 无取消标记，断开连接清空邀请后，该回调仍可能重新创建邀请。核心 API 的断开处理不能撤销已经排队的应用回调；此行为通过延迟客户端任务的回归测试在旧代码上复现。

这是资源占用与应用生命周期隔离问题。远端仍须通过核心 API 的身份和 AEAD 检查；没有发现这里能绕过玩家/路由授权访问任意本地端口。

## 修复

- 控制与隧道请求统一进入待处理登记表：最多 64 个、每玩家最多 16 个，玩家名忽略大小写。核心 API 池较小时仍受其更低容量约束。超额请求立即关闭，不提交读取任务，也不增加提示洪泛。
- 从接纳时起使用单调时钟固定计算 30 秒期限；分段到达的字节不续期。控制消息须完成解析和认证 EOF；隧道须完成授权头及连接组接纳。等待拒绝回复的 EOF 也仍受待处理期限约束。
- tick 到期时关闭 socket、唤醒读取并释放容量。处理控制消息、连接本地 TCP 前再检查期限和取消标记，避免超时内容在下一个 tick 前触发动作。
- 断开连接关闭全部待处理连接；客户端排队的控制回调必须重新检查任务状态，已取消任务不能生成邀请或执行其他控制动作。
- 隧道连接先加入授权连接组，再移出待处理登记表，避免断开/撤销在两者交接时漏掉连接。正常建立后继续使用原有每路由八条连接限制、双向半关闭和撤销逻辑，不受这项 30 秒元数据期限限制。
- 读取任务提交被拒绝、处理失败和完成时均清理任务状态。预期的期限/取消结束不再额外输出读取失败提示。

没有更改控制包、隧道帧、核心公开 API、存储格式或最低 Krypt04Mcg 版本要求。主项目与 `Krypt04mcg-plugin` 无需为本次修复同步。超过期限的合法慢速握手和超出待处理配额的合法连接突发也会被关闭，调用端需重试。

## 验证

- 旧代码首次运行七项新增边界测试，七项均失败，涵盖慢速头部、控制包缺少 EOF、断开清理、单玩家与全局容量、晚到控制包和晚到授权头。其中部分失败还暴露了取消后的读取任务未及时退出。
- 将旧 `ForwardingManager` 单独编译到仓库外的测试输出，运行延迟控制回调的用例：一项测试失败，断开后执行排队回调仍创建了邀请。没有替换工作树实现，也没有覆盖修复后的测试报告。
- 最终新增十项回归测试全部通过；除上述边界，还覆盖拒绝连接等 EOF 的到期释放、断开后排队回调失效，以及已建立连接可继续运行并正常撤销。
- Fabric `gradle build --no-daemon --max-workers=2` 成功：17 项单元测试、32 项管理器回归测试、3 项 IPv6 优先模式验证，合计 52 次测试执行；失败、错误和跳过均为 0。
- NeoForge `gradle -p neoforge build --no-daemon --max-workers=2` 成功；该变体没有独立测试源码，不能算作额外执行了测试。
- 原有碎片化控制消息、有效 EOF、双向大响应、路由存储、旧协议拒绝、授权替换、撤销和停用生命周期测试继续通过。
- 使用 Java 25、Gradle 9.5.1；生产代码仍针对真实核心 API 编译，管理器回归通过可控时钟、管道 socket 和延迟客户端任务替身运行。没有实际启动 Minecraft 联机。

本轮同时查看了主项目的二进制包边界、解压限制及插件中继路径，未确认另一项需要修改的漏洞。原始流中继的吞吐行为保持不变；持续反复请求、多人协同占槽、已授权端点的滥用及完整依赖扫描仍不在本次修复的保证范围内。
