# 反向转发授权文件安全审查（2026-10-08）

## 问题与修复

`RouteStore.save` 原先始终写入 `routes.dat.tmp`，随后替换正式文件。预先放置的同名符号链接会使写入截断并覆盖链接目标。`load` 未检查最终文件或父目录链接，也没有将授权文件、目录显式限制到所有者；悬空最终链接被当作空状态。

修复后，读取和保存检查整个存储路径，拒绝符号链接、悬空链接和特殊路径。目录与授权文件使用 POSIX `700`/`600` 或仅所有者 ACL；不支持权限限制的文件系统会报错。写入先验证和序列化有效状态，再在私有目录中创建唯一临时文件，不跟随临时链接写入，优先原子替换正式文件，并在失败时清理临时文件。不支持原子移动时保留原有普通替换兼容行为。

`routes.dat` 二进制格式和 UUID/玩家授权绑定没有改变。既有普通文件会在加载时收紧权限，链接存储需迁移到普通本地目录。存储保护在本仓库实现，不依赖新版核心内部工具，保留 Krypt04Mcg 0.23.0 的最低版本要求；未修改网络协议或服务端插件。

这是本地文件完整性与隐私风险，需要攻击者能预先放置文件链接或访问原文件；未发现远端能单独创建这些链接的路径。所有者权限不防御相同操作系统账户下的恶意进程；路径检查不构成完整的并发文件系统竞态防护。

## 验证

- 修复前 `RouteStoreTest` 的四项新测试全部失败，原有往返测试通过：固定临时链接覆盖、最终文件链接读取/替换、父目录及悬空链接、文件与目录权限。
- 修复后 Fabric `gradle build --no-daemon --max-workers=2` 成功：17 项单元测试、22 项管理器回归测试、3 项 IPv6 优先模式测试全部通过，失败、错误、跳过均为 0。
- 错误玩家撤销不写盘的既有测试改用正式文件修改时间判断，避免随机临时文件改造使旧的固定临时文件断言失去验证作用；合法撤销与授权生命周期测试继续通过。
- NeoForge `gradle -p neoforge build --no-daemon --max-workers=2` 成功；该变体无独立测试源码，不能记为额外运行了测试。
- 使用 Java 25、Gradle 9.5.1 和同工作区已验证的 Krypt04Mcg 0.27.4 Fabric API 编译依赖。四项新增存储测试在本机均执行，没有因链接或 POSIX 权限能力缺失而跳过。

Windows ACL、实际游戏联机和完整依赖安全扫描未在本轮验证。主项目的群组、缓存和历史文件修复记录在 `Krypt04Mcg` 仓库同名审查文档。
